# 协议迁移与发布说明

LeviLamina 协议版本 1 引入了一套官方支持的、类型化的网络交互接口，供远程客户端与专用服务器模组协同工作。它增加了模组专属命名空间、模块与特性协商、基于模式（Schema）选取的 Payload、有界编解码器、可撤销会话、生命周期事件以及服务器端扇出（Fan-out）发送。

这是一套全新的 API，而非面向既有原始数据包通道的透明兼容层。现有的对端必须协同更新，或者在协调完成迁移之前继续保留在其先前的传输层上。

## 迁移现有的 LeviLamina 通道

针对每个旧有的逻辑消息：

1. 确认所属模组，并在其清单中声明稳定的 `protocolNamespace`；
2. 将相关的消息组织归类到本地协议模块中；
3. 为每条消息赋予稳定的本地 Payload 名称，并指定确切的一个传输方向；
4. 将原始的 `BinaryStream` 访问替换为基于有界 `Encoder`/`Decoder` 的编解码器；
5. 将记录好的当前字节含义分配为模式 1；
6. 基于合法的 Payload 数据大小设置最大数据体大小，而非直接使用传输层的硬性上限；
7. 在客户端和服务器目标端上注册相互匹配的声明；
8. 在模组处于启用状态的整个生命周期内保留仅移动的注册令牌；
9. 发送前先获取处于活跃状态的已协商 `Session`，并对所有 `Expected` 失败进行处理；
10. 仅在明确不需要混合版本部署行为后，再移除旧有的通道。

切勿通过硬编码将旧有的数字运行时 ID 移植到新 API 中。协议运行时 ID 是从完整的稳定文本 ID 派生而来的，并在协商期间进行严格验证。

如果旧消息是双向的，请将其拆分为两个独立的类型和 ID。如果旧消息依赖于无界字符串、列表、NBT 文档或原始字节块，请在迁移前定义语义字段长度限制。

## 移植 Fabric Custom Payload

Fabric 风格的 Custom Payload 通常可按如下方式对应映射：

| Fabric 概念 | LeviLamina 协议概念 |
| --- | --- |
| Mod ID 命名空间 | 清单中的 `protocolNamespace` |
| 通道或 Payload 标识符 | 模块名称 + Payload 名称 |
| `CustomPayload` record/class | C++ Payload 值类型 |
| `PacketCodec` | 使用 `Encoder` 和 `Decoder` 的 `PayloadCodec` |
| C2S/S2C 注册 | 确切的一个 `PayloadDirection` 以及目标端特有的处理器注册 |
| 连接能力检查 | `SessionView::findPayload` 或发送操作的返回结果 |
| 网络回调 | 端点游戏线程上的 `PayloadHandler<T>` |

请勿机械地直译 Java 的序列化辅助工具。应当将整数表示方式、UTF-8 长度限制、集合元素数量、枚举校验以及尾随字节行为作为全新的有界网络传输契约重新评估。

## 移植 Forge 或 NeoForge 通道

`SimpleChannel` 或类似通道通常会转变为一个协议模块。消息注册会转变为各个独立且稳定的 Payload ID，而非依赖注册顺序的辨别符（Discriminator）。协议版本范围、特性、Payload 模式和需求策略取代了原先单一粗放的通道版本判断谓词。

在移植过程中请避免带入以下 Java 习惯假定：

- 注册顺序并不是稳定的消息标识；
- 类名不是网络 ID；
- 同一个处理器无法同时安全地在两端逻辑中运行；
- LeviLamina 协议内部不提供隐式的工作入队（Enqueue-work）行为；
- 协商成功的模组并不构成客户端所请求游戏操作的鉴权许可。

LeviLamina 处理器已经在受支持的端点游戏线程上运行。耗时或阻塞式的模组工作必须显式卸载至异步线程，且任何后续响应都必须回到该端点线程，并重新检查会话世代。

## 滚动灰度部署

对于可以平滑降级的功能：

1. 在两端将模块和 Payload 均发布为可选（Optional）；
2. 当会话/能力不存在时，保持旧有行为或仅禁用新功能；
3. 通过 `SessionView` 观察协商暴露的协议能力；
4. 仅在后续协调一致的发布中，移除回退代码或收紧需求策略。

对于缺少对端组件就无法安全运行的功能，请声明正确的模块/Payload 需求策略，并接受不兼容的 LL 对端将导致协商失败这一事实。如果服务器必须拒绝任何没有 LeviLamina 发现标记的客户端，还必须额外设置 `requireLoader`；单独的模块需求策略仅在 LL 协商开始后生效。

协议不支持动态重新协商。安装、启用、禁用或替换声明都会导致受影响的活跃会话关闭；请在两端均达到预期的部署状态后再行重新连接。

## 版本 1 发布边界

首个发布版本支持远程 LeviLamina 客户端连接至专用 LeviLamina 服务器。LL 到原版以及原版到可选 LL 服务器的登录过程仍表现为普通的 Minecraft 会话，不附带协议 Payload。

该版本不支持局域网/本地单人托管、任意线程发送、动态重新协商、流式传输、透明分片或 `BulkTransfer`。

建议先从[创建协议 Payload](creating_payload.zh.md)开始，随后遵循[注册协议模块与 Payload](registering_payload.zh.md)。
