# LeviLamina 协议

LeviLamina 协议是模组化客户端与专用服务器之间交换类型化、模组自定义 Payload 的官方支持方式。它提供了服务发现、功能与版本协商、有界序列化、会话生命周期管理，并保持与普通 Minecraft 登录过程的兼容性。

该协议不会取代 Minecraft 的底层网络。Minecraft 依然负责连接建立、身份验证、加密、压缩、可靠性保证、保序、数据包分片与重组。LeviLamina 通过现有的 Minecraft 传输层运载其控制消息与协商后的 Payload，并在调用模组代码之前对其进行严格校验。

## 何时使用

当某项功能需要客户端与服务器协同工作时，请使用该协议，例如：

- 向服务器提交操作的客户端界面；
- 由客户端覆盖层（Overlay）显示的服务器状态；
- 原版数据包无法表达的额外玩法状态；
- 从 Java 版模组移植过来的功能（此前使用 Fabric Custom Payload 或 Forge/NeoForge 网络通道）。

仅在服务器端运行、且已通过命令、表单、事件或原版数据包工作的模组通常不需要协议模块。纯视觉效果的纯客户端模组同样不需要。

## 支持的部署拓扑

版本 1 支持专用 LeviLamina 服务器与远程 LeviLamina 客户端之间通信。仅当两个端点均启用协议、完成协商并完成普通 Minecraft 登录后，协议会话才会建立。

| 客户端 | 专用服务器 | 结果 |
| --- | --- | --- |
| 启用 LeviLamina 协议 | 启用 LeviLamina 协议 | 协商出兼容的模块与 Payload。 |
| 启用 LeviLamina 协议 | 原版（或非 LeviLamina 服务器） | Minecraft 登录正常继续；不会创建协议会话。 |
| 原版或禁用协议 | LeviLamina，可选加载器策略 | Minecraft 登录正常继续；不会创建协议会话。 |
| 原版或禁用协议 | LeviLamina，强制加载器策略 | 登录被拒绝，并提示兼容性原因。 |

在版本 1 中，本地单人世界和局域网世界被有意归类为非协议 Minecraft 会话。完整支持范围请参阅[限制与约束](limitations.zh.md)。

## 模块、Payload 与会话

模组可以注册一个或多个协议模块。每个模块声明其语义化版本、兼容的模块协议范围、特性（Feature），以及是否在客户端、服务器、两端或都不强制要求。一个 Payload 隶属于一个模块，并包含：

- 稳定的本地名称；
- 确切的一个传输方向：客户端到服务器（Client-to-Server）或服务器到客户端（Server-to-Client）；
- 一个或多个支持的模式版本（Schema Version）；
- 必须（Required）或可选（Optional）的兼容性策略；
- 编码后的数据体大小限制；
- 编解码器（Codec），以及在接收端点上的处理器（Handler）。

LeviLamina 根据所属模组清单（Manifest）中的命名空间派生出完整的模块和 Payload 标识符。协商过程会选择兼容的模块、Payload、模式、特性及大小限制。未协商成功的 Payload 无法发送，也不会分发给其处理器。

`Session` 是指向某个协商端点世代（Generation）的可撤销句柄。只有在协议协商和 Minecraft 登录均成功后，它才会变为活跃状态。断开连接、超时、注册表变更、运行时关闭或重新连接都会使旧会话失效。因此，即使此前获取的会话是有效的，代码也必须妥善处理 `Expected` 失败结果。

## 安全契约

在调用模组编解码器或处理器之前，协议层会检查连接世代、会话状态、Payload 标识、方向、模式、声明长度、协商后的大小限制以及速率配额。注册令牌与模组所有者绑定，并在模组的所有者 disable 回调或动态库卸载可能导致回调代码失效之前被排空（Drain）。

处理器在端点游戏线程上同步执行。它们应当迅速完成语义输入验证，且只应将生命周期和取消操作完全由模组自身管理的工作卸载到异步任务中。在版本 1 中，协议发送同样限制在相应的端点游戏线程中。
