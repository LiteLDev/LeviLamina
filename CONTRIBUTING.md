# Contributing to LeviLamina

Thank you for helping out! This file is for people who work on LeviLamina itself: the loader, its API, its headers
and its documentation. To *use* LeviLamina or write mods for it, start with the
[tutorials](https://levimc.org/tutorials/) and the [documentation](https://levimc.org/LeviLamina/).

Everyone taking part follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Ways to contribute

- **Report a bug or ask for a feature**: [open an issue](https://github.com/LiteLDev/LeviLamina/issues/new/choose)
  with the form for it. Include the LeviLamina and game versions and the server or client log.
- **Ask for a Minecraft function**: functions marked `MCNAPI` are not exported yet; request them in
  [mcapi-requests](https://github.com/LiteLDev/mcapi-requests/issues/new).
- **Fix or improve code or docs**: fork the repository, make your change on a branch and open a pull request
  against `main`. Small, focused pull requests are reviewed fastest; for a large change, open an issue first so we
  can agree on the approach.

| [AGENTS.md](AGENTS.md) | the repository layout and the project's rules in short: editing the generated headers in `src/mc`, containers, error handling, changelog and commit conventions (written for coding agents, useful for everyone) |

Before you open a pull request:

1. Build the configurations your change touches. A change to a public header must compile with both
   `--target_type=server` and `--target_type=client`; CI builds every combination of server/client,
   debug/release and tests on/off, and warnings matter.
2. Run `python scripts/format_all.py` to apply `.clang-format`.
3. Add user-visible changes to the `## [Unreleased]` section of [CHANGELOG.md](CHANGELOG.md).
4. Write commit messages as [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`,
   `chore:`, `refactor:`, …).

## Working on the docs

The documentation site at <https://levimc.org/LeviLamina/> is built from `docs/main/`:

- Pages are in `docs/main/contents/`, in English (`page.md`) and Simplified Chinese (`page.zh.md`). Traditional
  Chinese is generated from the Simplified pages. Change both languages in the same pull request when you can.
- New pages are registered in the `nav` of `docs/main/docs.config.ts`, with the Chinese label of titled entries in
  `navTranslations.zh`. A moved or removed page gets an entry in `redirects` so its old URLs keep working.
- The site keeps guides and reference. Step-by-step tutorials for newcomers (install a server, play with mods, your
  first mod) are on [levimc.org/tutorials](https://levimc.org/tutorials/), in the
  [LiteLDev/liteldev.github.io](https://github.com/LiteLDev/liteldev.github.io) repository (`tutorials/`); guides
  for working on LeviLamina itself live in `docs/contributing/` and this file, not on the site.
- Markdown follows MkDocs / Python-Markdown conventions: 4-space list nesting, `!!! note` admonitions,
  `=== "Tab"` tabs, and links to other pages as relative `.md` paths.

The site is built with levimc-kit, which `npm ci` downloads into `docs/main/kit/` (git-ignored; never edit it).
With Node.js 24, from `docs/main`:

```sh
npm ci
npm run typecheck   # tsc over docs.config.ts and the kit
npm run build       # → dist/; prints unresolved links and missing anchors
npm run preview     # http://127.0.0.1:4173/LeviLamina/
npm run linkcheck   # internal links, anchors and redirects of dist/
npm run dev         # dev server with hot reload
```

The C++ Reference (`/LeviLamina/api/`) is generated by Doxygen from the headers with `docs/api/Doxyfile`; CI builds
it with the docs' header (`docs/main/kit/static/doxygen/gen-header.mjs` over the docs build's `dist/_kit/nav.json`)
and merges it into the site.
