# Contributing to LeviLamina

Thank you for helping out! This file is for people who work on LeviLamina itself: the loader, its API, its headers
and its documentation. To *use* LeviLamina or write mods for it, start with the
[tutorials](https://levimc.org/tutorials/) and the [documentation](https://levimc.org/LeviLamina/).

Everyone taking part follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Ways to contribute

- **Report a bug or ask for a feature**: [open an issue](https://github.com/LiteLDev/LeviLamina/issues/new/choose)
  with the form for it. Include the LeviLamina and game versions and the server or client log.
- **Ask for a Minecraft function**: functions marked `MCNAPI` are not exported yet; request them in
  [mcapi-requests](https://github.com/LiteLDev/mcapi-requests/issues/new).
- **Fix or improve code or docs**: fork the repository, make your change on a branch and open a pull request
  against `main`. Small, focused pull requests are reviewed fastest; for a large change, open an issue first so we
  can agree on the approach.

## Working on the code

| Guide | What it covers |
| ----- | -------------- |
| [Building LeviLamina](docs/contributing/building.md) ([中文](docs/contributing/building.zh.md)) | tools, `xmake` options, server/client and test builds, dependencies, version numbers, CI |
| [C++ style](docs/contributing/cpp_style.md) ([中文](docs/contributing/cpp_style.zh.md)) | naming, comments, formatting |
| [AGENTS.md](AGENTS.md) | the repository layout and the project's rules in short: editing the generated headers in `src/mc`, containers, error handling, changelog and commit conventions (written for coding agents, useful for everyone) |

Before you open a pull request:

1. Build the configurations your change touches. A change to a public header must compile with both
   `--target_type=server` and `--target_type=client`; CI builds every combination of server/client,
   debug/release and tests on/off, and warnings matter.
2. Run `python scripts/format_all.py` to apply `.clang-format`.
3. Add user-visible changes to the `## [Unreleased]` section of [CHANGELOG.md](CHANGELOG.md).
4. Write commit messages as [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`,
   `chore:`, `refactor:`, …).

## Working on the docs

The documentation site at <https://levimc.org/LeviLamina/> (Simplified Chinese: <https://levimc.org/zh-Hans/LeviLamina/>) is
built by levimc.org from the [LiteLDev/liteldev.github.io](https://github.com/LiteLDev/liteldev.github.io/tree/main/docs/LeviLamina) repository: edit the pages in
`docs/LeviLamina/` there and open the pull request on that repository. The C++ Reference
(<https://levimc.org/LeviLamina/api/>) is generated by Doxygen from this repository's headers during that build.

Tutorials for newcomers are on [levimc.org/tutorials](https://levimc.org/tutorials/), in the same repository
(`tutorials/`); guides for working on LeviLamina itself live in `docs/contributing/` and this file, not on the site.
